# 产品愿景与路线

## 用户与结果

面向在可信本机项目中工作的数学建模者与宿主代理。产品把问题输入、能力版本、参数、
Attempt、独立 Validation、制品和哈希关系保存在可追踪项目中，使一次数学计算可复核、
可恢复、可复现，而不把宿主或数据库细节带进数学实现。

M1 是可信同步短任务基线：应用 `0.2.0`、MCP 协议 `2025-11-25`、公共契约 `1.0.0`
和数据库 Schema `2`。原六工具与 C1 批准的四个预览工具共同构成当前 `TOOL_NAMES`。

## 历史探针与哈希承诺

M1a-0 只是 48 小时非生产可行性探针，证明官方 Codex 能经真实 STDIO MCP 完成一次求根。
它不是稳定契约、正式能力或 M1a 完成替代品。M1a 仅承诺固定向量与同环境重复执行的 hash smoke；
完整 RFC 8785 符合性、溯源和通用/项目向量由 B2/M1b 独占拥有。

## 路线

顺序固定为 `M1 → M2 → M2.5 → M3`：

- M1：可信同步短任务、SQLite、内容寻址制品、稳定 1.0 契约和独立验证。
- M2：用户文件、MMIR 与受控数据导入。
- M2.5：受控计算 worker、通用硬超时和资源限制。
- M3：经批准的 ODE、优化与统计能力。

C1 已按[批准补充](../superpowers/specs/2026-07-23-cumcm-2022-a-q1-contest-vertical-slice-design.md)
提前拉取一个专用短生命周期 worker 和 MMIR/制品切片；这不是 M2/M2.5 全部完成。

## 非目标

M1 不声称通用硬进程隔离、OCR、UI、多用户服务、自动论文写作、动态插件安装或额外数学能力。
也不建立任务队列、worker 池、第二存储、通用工作流引擎或 External Plugin SDK。

实现边界见[架构概览](../architecture/overview.md)，完成证据见[发布验证](../operations/release-verification.md)。
